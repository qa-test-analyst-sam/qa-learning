05 / AI FOR QA · BEGINNER

Claude AI testing

Use Claude as a thoughtful assistant for test planning and analysis, while keeping evidence, product context, and final decisions in the hands of the tester.

SELF-PACED5 LESSONSRESPONSIBLE AI USE

What you will learn

  • Give Claude clear requirements, boundaries, and output formats.
  • Use it to brainstorm scenarios, edge cases, and test data.
  • Review AI-generated ideas for accuracy, relevance, and duplication.
  • Protect private data and preserve human review in the workflow.

Course lessons

1. Give the assistant useful context

Describe the feature, user roles, acceptance criteria, constraints, and what you want back. Ask for a specific structure, such as a table with scenario, setup, action, expected result, and risk. State assumptions and ask the assistant to label any it makes. Clear prompts make the response easier to review, but do not guarantee correctness.

2. Expand a test idea

Ask Claude to brainstorm normal, boundary, negative, accessibility, and state-transition scenarios for a requirement. Request concise cases and a short explanation of the risk each one covers. Then compare the suggestions with product rules, existing coverage, and real user behavior. Keep the cases that add value and rewrite any that are vague or redundant.

3. Use it to review test artifacts

Claude can help critique a bug report for missing reproduction details, turn notes into a first draft, or explain unfamiliar code and logs. Give only the minimum information needed. Verify every factual claim against the application, source material, or a reproducible observation. Treat generated code and test data as drafts that need review before use.

4. Protect data and evaluate limits

Follow your organization's AI policy. Do not paste credentials, personal information, customer records, unreleased product details, or proprietary source code into a service unless that use has been explicitly approved. AI output can sound confident while being wrong, omit rare cases, or reflect bias in its examples. Record where human verification is required.

5. Practice: review a checkout requirement

Use a fictional requirement: “A signed-in customer can apply one valid discount code before paying.” Ask Claude for a risk-based scenario list in a table. Review whether it covers expired and invalid codes, minimum order value, repeated application, removal, currency, and totals. Correct the expected behavior using your stated rules and mark unresolved questions for the product owner.

Takeaway

Claude can help you think of questions faster. The tester remains responsible for validating the suggestions and protecting the information shared with the tool.
