ADVANCED SECURITY · INTERMEDIATE

Security testing

Build a risk-based security test approach for web applications. Examine trust boundaries, identity, permissions, input handling, and sensitive data using safe, authorized environments.

SELF-PACED5 LESSONSHANDS-ON PRACTICE

What you will learn

  • Create a lightweight threat model from user journeys and data flows.
  • Test authentication, authorization, session handling, and input boundaries.
  • Record security findings with clear impact and safe reproduction evidence.
  • Choose follow-up checks based on risk and evidence.

Course lessons

1. Map assets, users, and trust boundaries

Identify data and actions worth protecting: accounts, payment details, personal records, administrative controls, and service credentials. Sketch who can reach each feature and what they can do. Note where trust changes, such as a browser request entering an API. Use the map to focus on plausible harm.

2. Review identity and access control

Check sign-in, sign-out, recovery, session expiry, and account changes. Compare what an anonymous user, a standard user, and an administrator can see and change. Try approved test accounts against resources owned by another account and verify access is denied. Never use real customer data.

3. Probe input and state safely

For text, file, and query inputs, examine length limits, encoding, unexpected types, and invalid values. Verify server-side validation and safe errors. Use a deliberately vulnerable local lab for exploit demonstrations; on a real product, follow the written scope and avoid destructive payloads.

4. Check sessions and sensitive data

Look for secrets or personal information in URLs, browser storage, logs, errors, and responses where they do not belong. Check that sign-out or password changes invalidate sessions according to requirements. Confirm protected actions require the right identity and permission.

5. Practice: test a shared document feature

Create two approved test accounts and a private document owned by the first. Check view, edit, share, revoke, and direct-link access by each account. Include signed-out access and a revoked share link. Capture safe evidence and summarize the highest-impact risk without tokens or private data.

Takeaway

Use a focused, documented approach. Choose checks based on risk, preserve useful evidence, and make the next quality decision clear.
