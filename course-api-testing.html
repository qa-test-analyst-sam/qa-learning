03 / INTEGRATION · BEGINNER

API testing

Test the service contract directly: inputs, status codes, response data, authorization, and the edge cases that user interfaces may not expose.

SELF-PACED5 LESSONSHTTP FUNDAMENTALS

What you will learn

  • Read requests and responses using HTTP methods, headers, and bodies.
  • Validate status, schema, values, and important business rules.
  • Check authentication, authorization, and negative scenarios safely.
  • Keep test data isolated and make API checks repeatable.

Course lessons

1. Read the request and response

An API request combines a method, URL, headers, and sometimes a body. GET commonly retrieves data, POST creates or triggers an action, PUT replaces a resource, PATCH updates part of one, and DELETE removes one. Inspect the status code, response headers, body, and timing. Use the service's documented contract as your baseline.

2. Validate more than status

A 200 response alone does not prove the operation is correct. Check that required fields exist, types and formats are valid, values match the request, and business rules hold. For a created resource, confirm its identifier and verify it can be retrieved. For errors, check that the response is safe, understandable, and consistent with the contract.

3. Cover boundaries and failure paths

Try missing fields, invalid formats, unknown identifiers, duplicate requests, unsupported methods, and values at documented limits. Check that the service rejects unauthorized requests and that one user cannot access another user's data. Use test accounts and approved environments; never probe systems you are not authorized to test.

4. Make checks repeatable

Keep environment URLs and credentials outside shared test files. Create unique data or reset fixtures so one run does not break the next. Avoid depending on a particular execution order. Record the request and response details needed to debug a failure, while masking tokens and personal data in logs.

5. Practice: test a notes endpoint

Using a local or approved practice API, create a note, validate its returned identifier and content, retrieve it, update one field, and delete it. Then repeat with missing content and an invalid identifier. For every operation, state the expected status, response shape, and side effect before sending the request.

Takeaway

Strong API tests verify the contract and the business outcome, including the cases where the service must refuse a request.
