04 / PERFORMANCE · BEGINNER

Performance testing

Plan a realistic load experiment, choose measurements that matter, and turn the results into an actionable conversation about capacity and user experience.

SELF-PACED5 LESSONSPLANNING AND ANALYSIS

What you will learn

  • Distinguish load, stress, spike, and endurance testing.
  • Choose response-time, throughput, and error measurements.
  • Model realistic users and workloads from evidence.
  • Read results alongside infrastructure and application signals.

Course lessons

1. Start with a question

Define the decision the test should inform: for example, whether a release can support expected peak traffic while meeting a response-time target. Agree on the environment, duration, workload, success criteria, and safety limits. Performance tests can affect shared services, so coordinate with owners and use an approved environment.

2. Choose the right workload

A load test models expected usage, a stress test explores limits, a spike test examines a sudden change, and an endurance test looks for degradation over time. Use production-like traffic patterns where permitted, including think time, a mix of actions, realistic data, and ramp-up. A single endpoint hammered at maximum speed rarely represents real user behavior.

3. Measure the user experience

Track response-time percentiles such as p50, p95, and p99 rather than relying only on averages. Also record throughput, error rate, saturation, and resource usage. Averages can conceal a slow experience for a meaningful share of users. Define thresholds before the run so the results are judged consistently.

4. Run controlled experiments

Establish a baseline, change one important condition at a time, and repeat runs when results are noisy. Keep application version, test data, and environment notes with the result. Correlate client-side timings with server, database, and dependency metrics. Separate a generator bottleneck from an application bottleneck before drawing conclusions.

5. Practice: model a peak hour

Sketch a small online store's peak-hour mix: browse products, search, view details, add to cart, and check out. Estimate the share and frequency of each action, define acceptable p95 response time and error rate, then design a gradual ramp-up and a stop condition. After a practice run, identify the slowest journey and propose the next experiment.

Takeaway

A useful performance test is a controlled experiment tied to a user-facing target, not just a large number of simulated requests.
